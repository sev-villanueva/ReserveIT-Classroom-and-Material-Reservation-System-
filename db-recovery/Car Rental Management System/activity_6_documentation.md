## 2. Backup & Disaster Recovery Strategy

To guarantee data integrity and business continuity for the Car Rental Management System, a comprehensive backup and recovery policy is implemented:

1. **Logical Backups (`pg_dump` / `pg_restore`):** Daily compressed custom-format archives of schema definitions and operational data (`rental`, `payment`, `customer`).

2. **Point-in-Time Recovery (PITR):** Continuous WAL (Write-Ahead Logging) archiving to allow restoration to any exact transaction timestamp in case of database corruption or hardware failure.

3. **Automated Backup Verification:** Regular restoration drills into a test database (`car_rental_test_restore`) to ensure backup archives are valid and fully functional.

## 3. PostgreSQL Backup & Recovery Scripts

### A. Automated Backup Script (`backup_car_rental.sh`)

```
#!/bin/bash
# =============================================================================
# COMP 018: Activity 6 - Automated Backup Script for Car Rental Management System
# =============================================================================

DB_NAME="car_rental_db"
DB_USER="car_rental_dba"
BACKUP_DIR="/var/backups/postgresql/car_rental"
TIMESTAMP=$(date +"%Y%m%d_%H%M%S")
BACKUP_FILE="$BACKUP_DIR/car_rental_backup_$TIMESTAMP.dump"

# Create backup directory if it doesn't exist
mkdir -p "$BACKUP_DIR"

echo "Starting backup for database: $DB_NAME..."

# Execute pg_dump in custom compressed format
PGPASSWORD="SecureDBA_Pass123!" pg_dump -U "$DB_USER" -h localhost -d "$DB_NAME" -F c -b -v -f "$BACKUP_FILE"

if [ $? -eq 0 ]; then
    echo "Backup completed successfully: $BACKUP_FILE"
else
    echo "ERROR: Backup failed for $DB_NAME." >&2
    exit 1
fi

# Retention policy: Remove backups older than 7 days
find "$BACKUP_DIR" -type f -name "car_rental_backup_*.dump" -mtime +7 -delete
echo "Old backups cleaned up successfully."

```

## 5. Backup & Recovery Best Practices

1. **Offsite Storage:** Production backups generated by automated scripts are transferred securely to remote cloud storage to protect against local hardware failures or site disasters.

2. **Credential Security:** Database credentials (`PGPASSWORD`) are injected via environment variables rather than hardcoded into backup scripts.

3. **Periodic Drills:** Monthly test restorations ensure recovery time objectives (RTO) and recovery point objectives (RPO) are met.
