## 2. Database Health & Maintenance Plan

To ensure optimal query performance, prevent table bloat, and maintain accurate statistics for the PostgreSQL query planner, the following maintenance routines are established for `car_rental_db`:

1. **Statistics Refresh (`ANALYZE`):** Run regularly on high-transaction tables (`rental`, `payment`, `vehicle`) so the cost-based optimizer uses accurate row estimates.

2. **Space Reclamation (`VACUUM`):** Run periodic `VACUUM` (and `VACUUM ANALYZE`) routines on tables with frequent updates/deletes to reclaim dead tuples and prevent performance degradation.

3. **Index Health Monitoring:** Inspect index usage via `pg_stat_user_indexes` to identify unused indexes and add missing foreign-key indexes.

## 3. PostgreSQL Maintenance & Tuning Script

The following script covers routine health checks, table statistics updates, index monitoring, and vacuum operations.

```
-- =============================================================================
-- COMP 018: Activity 5 - Database Maintenance & Performance Tuning Script
-- Target Database: car_rental_db
-- =============================================================================

-- 1. Update Statistics for Query Optimizer (ANALYZE)
-- Run ANALYZE on core operational tables to refresh planner statistics
ANALYZE VERBOSE public.rental;
ANALYZE VERBOSE public.payment;
ANALYZE VERBOSE public.vehicle;
ANALYZE VERBOSE public.customer;
ANALYZE VERBOSE public.inspection;

-- 2. Reclaim Storage and Remove Dead Tuples (VACUUM)
-- Vacuum high-traffic tables to prevent bloat
VACUUM VERBOSE public.rental;
VACUUM VERBOSE public.payment;
VACUUM VERBOSE public.vehicle;

-- 3. Check Table and Index Sizes (Storage Audit)
SELECT 
    schemaname AS schema_name,
    relname AS table_name,
    pg_size_pretty(pg_total_relation_size(relid)) AS total_size,
    pg_size_pretty(pg_relation_size(relid)) AS table_size,
    pg_size_pretty(pg_total_relation_size(relid) - pg_relation_size(relid)) AS index_size
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC;

-- 4. Identify Missing or Unused Indexes
SELECT 
    schemaname,
    relname AS table_name,
    idx_scan AS index_scans,
    pg_size_pretty(pg_relation_size(indexrelid)) AS index_size
FROM pg_stat_user_indexes
WHERE idx_scan = 0
  AND indexrelid NOT IN (
      SELECT conindid FROM pg_constraint WHERE contype IN ('p', 'u')
  )
ORDER BY pg_relation_size(indexrelid) DESC;

-- 5. Monitor Active Connection and Lock States
SELECT 
    pid,
    usename,
    client_addr,
    state,
    query_start,
    query
FROM pg_stat_activity
WHERE datname = 'car_rental_db'
  AND state != 'idle';

```

## 5. Maintenance Justification & Best Practices

1. **Preventing Optimizer Degeneration:** Frequent rentals and payments cause rapid row updates and insertions. Running `ANALYZE` ensures the PostgreSQL query planner chooses optimal index scans over sequential scans.

2. **Mitigating Table Bloat:** `VACUUM` prevents disk space wastage from dead rows generated by updates on dynamic tables like `rental` and `vehicle` status changes.

3. **Index Optimization:** Monitoring `pg_stat_user_indexes` helps identify redundant indexes that slow down `INSERT` and `UPDATE` statements without providing query benefits.
