## 2. Database Health & Maintenance Plan

To ensure optimal query performance for recruitment workflows, prevent table bloat, and maintain accurate statistics for the PostgreSQL query planner, the following maintenance routines are established for `applicant_management_db`:

1. **Statistics Refresh (`ANALYZE`):** Run regularly on high-transaction tables (`applications`, `applicants`, `interviews`) so the cost-based optimizer uses accurate row estimates.
2. **Space Reclamation (`VACUUM`):** Run periodic `VACUUM` (and `VACUUM ANALYZE`) routines on tables with frequent status updates and record modifications to reclaim dead tuples.
3. **Index Health Monitoring:** Inspect index usage via `pg_stat_user_indexes` to identify unused indexes and ensure optimal foreign-key index coverage.

## 3. PostgreSQL Maintenance & Tuning Script

```sql
-- =============================================================================
-- COMP 018: Activity 5 - Database Maintenance & Performance Tuning Script
-- Target Database: applicant_management_db
-- =============================================================================

-- 1. Update Statistics for Query Optimizer (ANALYZE)
ANALYZE VERBOSE public.applications;
ANALYZE VERBOSE public.applicants;
ANALYZE VERBOSE public.interviews;
ANALYZE VERBOSE public.positions;
ANALYZE VERBOSE public.departments;

-- 2. Reclaim Storage and Remove Dead Tuples (VACUUM)
VACUUM VERBOSE public.applications;
VACUUM VERBOSE public.applicants;
VACUUM VERBOSE public.interviews;

-- 3. Check Table and Index Sizes (Storage Audit)
SELECT 
    schemaname AS schema_name,
    relname AS table_name,
    pg_size_pretty(pg_total_relation_size(relid)) AS total_size,
    pg_size_pretty(pg_relation_size(relid)) AS table_size,
    pg_size_pretty(pg_total_relation_size(relid) - pg_relation_size(relid)) AS index_size
FROM pg_stat_user_tables
ORDER BY pg_total_relation_size(relid) DESC;

-- 4. Identify Missing or Unused Indexes
SELECT 
    schemaname,
    relname AS table_name,
    idx_scan AS index_scans,
    pg_size_pretty(pg_relation_size(indexrelid)) AS index_size
FROM pg_stat_user_indexes
WHERE idx_scan = 0
  AND indexrelid NOT IN (
      SELECT conindid FROM pg_constraint WHERE contype IN ('p', 'u')
  )
ORDER BY pg_relation_size(indexrelid) DESC;

-- 5. Monitor Active Connection and Lock States
SELECT 
    pid,
    usename,
    client_addr,
    state,
    query_start,
    query
FROM pg_stat_activity
WHERE datname = 'applicant_management_db'
  AND state != 'idle';
```

## 5. Maintenance Justification & Best Practices

1. **Preventing Optimizer Degeneration:** Frequent updates to application statuses (e.g., pending, reviewing, accepted, rejected) cause row modifications. Running `ANALYZE` ensures optimal query plans.
2. **Mitigating Table Bloat:** `VACUUM` prevents disk space wastage from dead rows generated by frequent edits in the `applicants` and `applications` tables.
3. **Index Optimization:** Monitoring `pg_stat_user_indexes` ensures that index overhead remains lean during recruitment bursts.
